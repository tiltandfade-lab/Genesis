# REALM-ENRICHMENT-WRITING — fold, regenerate, stats + narratable descriptions

## §0 The gap

`data/realm-bestiary.js` (1092 creatures) carries only `{name, cr, role, type, size, frame, model}`.
The source JSON (`dev/model-qa/realm-bestiary-draft.json`) ALREADY holds `summary` (5–10 word hook)
and `flavor` (1–3 sentence prose) per creature — **the generator drops them.** The icons batch
(`dev/model-qa/realm-bestiary-icons.json`, 219 curated entries with `source`/`sourceNote`) is not
yet folded. And no creature has a narratable `desc` or a curated stat presentation — a breach foe
narrates today as its generic SRD chassis.

**This lane's output feeds two consumers:** the STORY-WIRING lane (desc → codex → DM digest) and
the MODELING lane (the fold changes the net-new model queue — 207 + up to 23 icon net-news). So:
**fold FIRST, freeze the model queue off the regenerated data, then author prose.**

## §1 Unit W1 — the fold + review reshape (draft JSON is the editable source)

Edit `dev/model-qa/realm-bestiary-draft.json` ONLY (never data/realm-bestiary.js — generated):

1. **Fold the icons batch in:** merge each icons entry into its realm's array. Collision rule: an
   icon with the same name (case-insensitive) as an existing draft row REPLACES it (icons are the
   vetted, source-tagged versions). Carry `source`/`sourceNote` fields through — they are the legal
   provenance trail (PD/archetype/folklore) and MUST survive into the generated JS.
2. **SCAN-flag cleanup (mechanical only):** (a) every `frame` must exist in `data/bestiary.js` —
   fix or re-frame invalid ids; (b) exact-duplicate names within one realm → dedupe; (c) every
   `model: "net-new: …"` description must be concrete enough to model from (subject + silhouette
   read in ≤15 words) — sharpen vague ones, never invent new creatures; (d) suburb rows must sit
   inside the LOCKED 1980s-Americana register — flag (do not delete) any that don't into a
   `_review` array at the top of the file for Adam.
3. **Role/CR sanity:** each realm keeps a mook→elite→high→apex spread; report (don't force) any
   realm whose apex band is empty or whose CRs exceed the Tier-2 practical ceiling for common play.

**Gate:** a validation script pass (see W2's generator `--check` mode) reporting: total count,
per-realm counts, 0 invalid frames, 0 intra-realm dupes, net-new model count per realm.

## §2 Unit W2 — a real generator (`build/gen-realm-bestiary.py`)

The current data/realm-bestiary.js was generated ad-hoc (no committed generator — a drift trap the
edit-source→compile-artifact discipline forbids). Build `build/gen-realm-bestiary.py`:

- Reads `dev/model-qa/realm-bestiary-draft.json` (post-fold, the single source of truth).
- Emits `data/realm-bestiary.js` with the FULL per-creature shape:
  `{name, cr, role, type, size, frame, model, summary, flavor, desc?, traits?, source?}`
  (omit absent optional fields — no `desc:""` noise; keep the file readable, one creature per line).
- `--check` mode: validates without writing (frame ids vs data/bestiary.js, realm ids vs
  data/realms.js's frozen REALM_IDS, dupes, required fields) — this is W1's gate.
- Stamps the header `GENERATED by build/gen-realm-bestiary.py from dev/model-qa/realm-bestiary-draft.json — never hand-edit`.
- Register nothing new in manifest.json (data/realm-bestiary.js already registered); run
  `python3 build/check-manifest.py` after regenerating (module content changed).

**Gate:** check-manifest OK · `node dev/verify-realm-wiring.mjs` still green (field additions are
additive; the harness's name/frame assertions must not regress) · `--check` clean.

## §3 Unit W3 — the stat + description pass (the craft core)

Per creature, TWO additive fields authored into the draft JSON (then regenerate via W2):

1. **`desc`** — 2–4 sentences of ORIGINAL narratable prose the DM reads when the creature appears.
   Register rules: written in the realm's voice (data/realms.js one-line registers are the north
   star; REALM-BESTIARY-DRAFT per-realm intros are the style bible); sensory-first (what the PC
   sees/hears/smells before what it means); NO stats in prose, NO fake lore hooks (ADAM-REVIEW-2
   §2 note-register discipline — doers not pointers applies to prose too); present tense.
   `flavor` (concept note) stays — `desc` is the player-facing read, `flavor` the DM's concept.
2. **`traits`** — OPTIONAL curated stat presentation: only where the realm creature meaningfully
   diverges from its frame chassis. Shape: `{hp?, ac?, note?, actions?: [{name, text}]}` — small
   overrides + 0–2 signature actions max, written OGL/SRD-clean (mechanics derived from the SRD
   chassis, prose original; NEVER a copied stat block). Default = no traits (the frame is the law);
   expect ~10–20% of creatures to earn one. Apex/high roles get first claim.

**Batching:** one executor per realm (~100–120 creatures each, 11 batches), each handed: its
realm's register line + the realm intro from REALM-BESTIARY-DRAFT + 3 exemplar descs (authored in
the spec-lock step, one Grounded / one elite / one apex) + the ADAM-REVIEW-2 prose laws.
**Review gate per realm batch:** a second agent samples 15 rows against the register (voice match,
no pointers, no stat-leak, original prose) + spot-checks 5 traits for OGL-cleanliness; orchestrator
re-gates fails.

**Gate:** every creature has `desc`; regenerated JS parses; check-manifest OK; per-realm review
verdicts logged in this doc's §6 table when run.

## §4 Out of scope

No engine edits (STORY-WIRING consumes `desc` — separate spec). No model edits. No bestiary.js /
SRD chassis edits. No realm-table (Engine markdown) edits.
