# SPRITE-TRANSITION — creatures become sprites; the 3D engine keeps the stage

## Decision (Adam, 2026-07-09 — LOCKED; do not re-litigate)

1. **All creature/NPC/animal/kid/PC minis become 2D sprites** generated via OpenAI ImageGen from
   the `dev/model-qa/sprite-sheets/*.md` prompt files. Rationale: a solo dev can populate
   thousands of distinct minis this way; a huge creative pool for the DM beats a small bespoke
   3D roster. This REVERSES the "sprites RETIRED" ruling in DESIGN-GUIDE — T1 records the
   reversal in the decision registry.
2. **The three.js engine STAYS** and refocuses on what it's proven good at: trays, stage,
   architecture, props, per-room lighting (architectural > organic — the observed strength).
   Possible future texturing pass on 3D surfaces; out of scope here.
3. **Retire ≠ delete.** The 185-body whole-object roster remains on disk as a fallback tier.
   Resolution chain per creature: cut sprite → 3D whole-object → cuboid → blank meeple. The
   game never breaks on a missing sprite.
4. **PS1 look doubles down:** billboarded sprites on the 3D stage (the Doom/PS1 idiom), nearest-
   neighbor filtering, existing dither/vertex-snap pipeline untouched. **Sprites stand on the
   existing circular base discs (disc radius = SRD size, as today) and the sprite plane itself
   scales by creature size** — a Gargantuan dragon sprite must visibly dwarf a Medium PC sprite.
5. **Sheets are NOT uniformly arranged** (ImageGen grid discipline is imperfect). The pipeline
   therefore leans on blob-detection + fail-loud count mismatch + an ALWAYS-emitted human review
   contact sheet. Tagging = automated join from game data + a vision-scan + **Adam redline pass**
   overlay; never trust layout, never guess a slug.
6. **Foundry creature waves are DONE for now** (T1 re-scopes the doc); tray/prop/architecture
   modeling continues in the models lane.

## Shared data shapes (FIXED — all units code against these, enabling parallel builds)

**V2 sheet manifest** — `dev/sprite-manifests/v2-manifest.json` (generated by T2):
```json
{ "sheets": [ { "id": "gloom-monsters-1", "realm": "gloom", "kind": "monster",
    "sourceFile": "dev/model-qa/sprite-sheets/gloom.md", "sourceSection": "Monster sheet 1/5",
    "expected": 25,
    "cells": [ { "n": 1, "name": "Grinning Poppet", "slug": "spr-gloom-grinning-poppet", "cue": "..." } ] } ] }
```
`kind` ∈ monster|npc|domestic-animal|wild-animal|dungeon-animal|kid|pc|expansion. Slug scheme:
`spr-<realm>-<kebab-name>` (`pc-characters.md` → realm `pc`; `fantasy.md` → realm `fantasy`);
kebab strips punctuation/diacritics, collapses dashes; collisions fail generation loudly.

**Sprite registry** — `data/sprite-registry.js` (generated by T3; owns `SPRITE_REGISTRY`, a
plain global per house style, one entry per line):
```js
"spr-gloom-grinning-poppet": { realm:"gloom", kind:"monster", name:"Grinning Poppet",
  role:"mook", cr:0.25, type:"Construct", size:"Tiny", frame:"...", tags:["doll","domestic"],
  sheet:"gloom-monsters-1", cell:3, status:"pending" }
```
`status` ∈ `pending` (not yet cut) | `cut` (assets/sprites/<slug>.png exists). Join keys: cell
name ↔ `dev/model-qa/realm-bestiary-draft.json` creature name within the same realm (exact,
then case/punct-insensitive; unjoined cells emit with nulls + a WARN list — NEVER dropped).
**Hand overlay** — `dev/model-qa/sprite-tags-overlay.json`: `{ "<slug>": { tags:[...],
reusable:"unique|realm|cross-realm", redlined:true } }`, deep-merged last (the Adam redline
surface; vision-scan tags land here too, T5).
