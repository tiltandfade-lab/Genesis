# Stage A1/A2 Post-Merge Review — 2026-07-12

Scope: merged implementations `e411f072` (A1 one-room-literal) and `a994a7d7` (A2 ShotPlan),
reviewed on `master` after the room-shell compiler merge `ccfe5d14`.

## Verdict

A1 and A2 are sound foundations and are already merged into `master`. A1 genuinely removes neighbor
room geometry when production supplies the active `focusSegNum`; A2 is pure, deterministic, plain-Node
testable, and keeps camera policy outside `theater-boot.js` as intended.

Three review fixes landed before A3 consumes the API:

1. Beat-mode default camera distance now solves for the midpoint of the 18-25% medium-standee frame
   height band. The original distance fitted the whole room diagonal, so representative rooms from
   4x4 through 12x9 all failed the hard figure-height constraint (4x4 was too close; 6x6+ too far).
2. The 7% safe-frame constraint now includes projected figure extent. The original check considered
   only standee center points, allowing visible art to cross the boundary while passing.
3. A1 now fails closed when an explicit `focusSegNum` is invalid. Missing focus remains the deliberate
   whole-plan study/harness path; stale explicit focus produces no room geometry rather than revealing
   the whole dungeon.

## A1 Notes for Later Units

- The production source in `src/world/render.js` supplies `focusSegNum`, so active-room-only is live.
- Darkness portals are correctly derived from door `betweenSegs` and do not mutate mechanics.
- A3 should stamp `activeRoomId` onto the interior tray. Until then A2's neighbor-room constraint is
  intentionally exempt because `interiorBuildBoard` does not emit that field.
- The legacy `ITR_ACTIVE_ROOM_ONLY=false` path remains useful only for captures and diagnostics. Do
  not use it as a production fallback.
- Browser harnesses use fixed local ports. Run visual harnesses serially when confirming exit status.

## A2 Notes for A3

- `theater-shot.js` is not consumed by `theater-boot.js` yet. That is correctly A3 scope; A2 alone
  does not change the live camera.
- A3 must implement the documented two-argument hypothetical projector
  `project(worldPoint, cameraPose)`. The existing live-camera-only `projectWorldPoint` is insufficient
  for comparing candidate yaws without mutating the mounted camera.
- If `metrics.allRejected` is true, A3 must retain/fall back to the existing `focusRect` camera and
  report the reject reasons. Never blindly apply a rejected best-effort camera.
- Supply combat units with their exact rendered world positions when possible. The raw band/lane
  fallback is deliberately approximate and should not become the live integration path.
- Stamp the room-shell polygon into `ShotPlan.stage` when A3 integrates the later C4 compiler. A2's
  current `stageFromTray` uses active-room bounds because the compiler did not exist when A2 landed.
- The `hard_occlusion_area` score remains a truthful zero-valued slot until A4 supplies blocker
  geometry. Do not treat A2's camera score as occlusion-aware before A4.
