# Module Phasing — proof / playable MVP / ideal goal, per game module

Adam's ruling (2026-07-22): *every* module carries the three horizons, not just the dungeon
program. The PHASING-FRAMEWORK already governs the program (its per-question records live in
the wave phasing audits and roll up in the
[Feature-Promotion Ledger](../procedural-dungeon-direction/FEATURE-PROMOTION-LEDGER.md));
this register extends the same three-horizon discipline to the rest of the game so no module's
destination lives only as prose in an old spec.

Reading the columns: **Proof** = the smallest evidence this module's architecture works (for
built modules: the evidence that already exists). **Playable MVP** = what v1 must contain
(narrow breadth allowed; borderline stays in). **Ideal** = the accepted/aspirational
destination with its source. States: BUILT / PARTIAL / SPECCED / RULED (design accepted,
unspecced) / LEDGER (dungeon-program-owned — see ledger row). Nothing here re-decides a locked
ruling; every ideal cites its source, and unsourced entries are marked (proposed).
