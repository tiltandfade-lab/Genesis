## HQ2-1 — numeric coercion moves to the fold (the keystone)

**Subsumes findings:** dm.js:3075 (clock_advanced +1 sign-inversion, HIGH — the flagship),
dm.js:1571 (dmNum hand-picked onto 5 sites, HIGH), dm.js:2369 (item_changed.gold, MED),
dm.js:2916 (social_check.dc hand-rolled, MED).

**Bug (verified @ HEAD):** `dmNum(w,type,key,v)` (src/world/dm.js:1571-1580) is a hand-invoked
coercion+drift-ledger helper called at exactly **5 sites** (hp_changed.delta 1675, death_save.d20
1761, attack.d20/targetAC/magnitude 1898, charge_restore.n 2450, check.d20/bonus/reroll 3361).
`dmFoldPayload` (1520-1538) already iterates EVERY field of EVERY declared event (via
`DM_EVENT_FIELDS`, 1418-1514) for alias-folding + unknown-key drift — but does **no type coercion**.
So every OTHER math-bearing numeric field reaches its handler as the raw DM value:
- `clock_advanced` (3075): `d=(typeof p.delta==="number"?p.delta:1)` — a string `delta:"-1"` fails
  the `typeof` gate and falls back to the hardcoded `+1`, **silently inverting a declared setback
  into an advance** (the flagship). No warn, no ledger.
- `item_changed` (2369): `if(typeof p.gold==="number" && p.gold){…}` — a string `gold:"-50"` is
  silently dropped; `sh.gold` untouched, no drift line.
- `social_check` (2916-2917): hand-rolls `isFinite(Number(p.dc))` + clamp — coerces, but with NO
  console.warn / drift ledger line, unlike every sibling.
- Uncovered entirely (raw string → concat/NaN): `grapple.bonus`/`shove.bonus` (verified live:
  `15 + 2 + "2"` → `"172"`, margin 162 not 9), `temp_hp.n`, `resource_spent.n`, `item_split.qty`,
  `foe_morale.d20`, `gift.weight`, `condition_add.n` (ttl is object-shaped — see the table correction), and more.

**The fix (single mechanism):** add a per-event **`num:[…]`** tag to `DM_EVENT_FIELDS` naming each
field the handler does arithmetic/comparison on, and apply `dmNum` ONCE **inside `dmFoldPayload`**
for every tagged field. Then RETIRE the 5 hand-called `dmNum` sites and the 3 named ad-hoc
coercions. `dmFoldPayload` already returns a COPY `p` (never mutates `e.payload`) and is the single
gate every handler's `p.*` reads flow through — coercing there normalizes all sites at once.

## HQ2-2 — koCheckWake moves INSIDE advanceClock

**Subsumes:** play.js:513 (koCheckWake missing from passTime + instant-arrival paths, HIGH).

**Bug (verified @ HEAD):** `koCheckWake(w)` (dm.js:952-968) — the lazy KO-wake check whose own doc
comment (dm.js:949-951) says it is "called from **every** clock-advancing site" — is hand-invoked at
only **3** sites (play.js:289 pcMoveTo, dm.js:2264 rest, dm.js:3729 montage), while `advanceClock`
(src/world/state.js:78) is called at **16** sites. The UI `passTime` path (play.js:513-533,
"Rest until dawn"/montage) calls `advanceClock(w,min)` at :518 and **never** calls koCheckWake — so a
non-lethally-KO'd PC with a stamped `sh.ko.wakeDay/wakeMin` rests through their wake time and
`sh.ko` stays set, `hpCur` stuck at 0/unconscious. Same gap at the instant-arrival travel path
(play.js:271). The check belongs one level up, in the shared primitive.

### Changes
**1. `src/world/state.js:78`** — fold the wake check into `advanceClock`, guarded (state.js loads
before dm.js; `koCheckWake` resolves at call time). `koCheckWake` does NOT call `advanceClock`
(verified — it only reads `clockOf`/`livingSheet` and mutates the sheet), so **no recursion is
possible**; a re-entrancy guard is unnecessary but a cheap `_inAdvanceClock` flag is added as
defense-in-depth per the task, so a future koCheckWake that ever ticks the clock can't loop:
```js
// before
function advanceClock(w,minutes){const c=clockOf(w);const total=c.min+minutes;
  c.day+=Math.floor(total/1440);c.min=((total%1440)+1440)%1440;return c;}
// after — the KO-wake check now fires from THE one primitive every clock-advancing site shares
// (HOTFIX-QUEUE-2026-07-07 HQ2-2). Re-entrancy guard: koCheckWake never ticks the clock today, but
// if it ever does, the flag stops a loop.
function advanceClock(w,minutes){const c=clockOf(w);const total=c.min+minutes;
  c.day+=Math.floor(total/1440);c.min=((total%1440)+1440)%1440;
  if(!advanceClock._busy && typeof koCheckWake==="function"){
    advanceClock._busy=true; try{ koCheckWake(w); } finally{ advanceClock._busy=false; }
  }
  return c;}
```
**2. Remove the 3 now-redundant per-site calls** (koCheckWake is idempotent — `if(!sh.ko) return` —
so double-invoke was already harmless, but delete them for clarity): play.js:289 (inside pcMoveTo,
after the advanceClock it follows), dm.js:2264 (rest), dm.js:3729 (montage). **Verify each removal:
the advanceClock that PRECEDED the removed call is the one now doing the wake** — do not remove a
koCheckWake that follows some OTHER primitive.

### Edge cases (ruled)
- **World creation / prep** ticks the clock before a PC exists: `koCheckWake` guards on
  `livingSheet(w)` null → early return. Safe.
- **KO'd PC woken mid-rest** (rest restores HP AFTER the tick): koCheckWake sets `hpCur=max(hpCur,1)`
  and clears `sh.ko`; the subsequent rest-restore then heals further — correct, no double-heal.
- **advanceClock called with a NEGATIVE minutes** (none today, but time-rewind is theoretically
  reachable): `now<wakeAt` → koCheckWake returns without waking. Safe.
- Do NOT also call koCheckWake from the 13 other advanceClock sites — the primitive now covers them.

### Don't touch
`koCheckWake`'s body, `clockOf`, `restRiders`, `pcMoveTo`'s other work.

**Subsumes:** dm.js:3492 (collapse ground-zone no-op, MED).

**⚠ Re-verification note (read before building):** the review flagged this as "violates its own

engine NEVER auto-moves or auto-damages a combatant"). So this is a **design change**, not a
conformance fix — it changes a SPEC-LOCKED doc and must ship WITH the doc edit + Fable's gate.

adjudicates — exactly as its siblings `flood` (3488-3491) and `hole` (3517-3520) already do (they
push `cm.scene.hazardZones` with `revealed:true` and let the DM decide `hazard_tick`). A marker is
NOT an auto-move or auto-damage, so DM-agency holds.
